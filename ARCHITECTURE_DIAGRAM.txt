===============================================================================
DATA FLOW: SENDING NOTIFICATIONS
===============================================================================

  1. USER ACTION
     └─> User clicks "Send to Slack" button in UI
  
  2. FRONTEND
     └─> React component calls: POST /notifications/send?min_score=5.0
  
  3. API ROUTER (notifications.py)
     └─> Receives request
     └─> Calls: db.get_unsent_high_profit_articles(min_score=5.0)
  
  4. DATABASE (persistent_database.py)
     └─> Query: SELECT * FROM articles 
                WHERE profit_score >= 5.0 
                AND slack_notified = 0
     └─> Returns: List of unsent articles
  
  5. SLACK NOTIFIER (slack_notifier.py)
     └─> Receives articles list
     └─> Builds Slack Block Kit message
     └─> HTTP POST to webhook URL
  
  6. SLACK API
     └─> Receives formatted message
     └─> Posts to configured channel
     └─> Returns: 200 OK
  
  7. DATABASE UPDATE
     └─> Marks articles as sent
     └─> UPDATE articles SET slack_notified = 1 WHERE id IN (...)
  
  8. API RESPONSE
     └─> Returns: {"success": true, "sent_count": 3, ...}
  
  9. FRONTEND UPDATE
     └─> Shows success alert
     └─> Refreshes status (pending count decreases)
     └─> Updates UI to show 0 pending

===============================================================================
ERROR HANDLING FLOW
===============================================================================

Try Block:
  └─> Send HTTP request to Slack
      │
      ├─> Success (200 OK)
      │   └─> Mark articles as sent
      │   └─> Return success response
      │
      ├─> Network Error (URLError)
      │   └─> Return error: "Network error: ..."
      │
      ├─> Slack API Error (status != 200)
      │   └─> Return error: "Slack API returned status ..."
      │
      └─> Other Exception
          └─> Return error: "Failed to send notification: ..."

Frontend Display:
  └─> Success response
      └─> Show green checkmark alert
      └─> Refresh status
  
  └─> Error response
      └─> Show red X alert
      └─> Keep pending count
      └─> Don't mark articles as sent

SECURITY CONSIDERATIONS
===============================================================================

✅ Webhook URL stored in environment variable (not in code)
✅ No sensitive data exposed in API responses
✅ Proper error handling (no stack traces to frontend)
✅ Database transaction locks for concurrent requests
✅ Input validation with Pydantic models
✅ Query parameter validation (min_score range: 0-10)
✅ No SQL injection (parameterized queries)
✅ CORS configured for specific origins
✅ Timeout on HTTP requests (10 seconds)

⚠️  Keep webhook URL secret!
⚠️  Don't commit .env file to version control
⚠️  Rotate webhook if exposed

===============================================================================
PERFORMANCE CONSIDERATIONS
===============================================================================

Database:
  • Index on profit_score for faster queries ✅
  • Index on slack_notified for filtering ✅
  • Efficient UPDATE queries with IN clause ✅
  • No N+1 queries (batch operations) ✅

Network:
  • Single HTTP request per batch (not per article) ✅
  • 10-second timeout to prevent hangs ✅
  • No retry logic (fail fast) ✅

Frontend:
  • Auto-refresh limited to 30 seconds ✅
  • Loading states to prevent double-sends ✅
  • Debounced button clicks ✅
  • Efficient React hooks (no memory leaks) ✅

Scalability:
  • Thread-safe database operations (locks) ✅
  • Singleton pattern for notifier ✅
  • Pagination possible for large article lists ✅
  • Batch size can be limited if needed ✅

TESTING SCENARIOS
===============================================================================

✅ Scenario 1: Fresh Install
   - Database migration creates slack_notified column
   - All articles have slack_notified = 0
   - Status shows all high-profit articles as pending

✅ Scenario 2: Send Notifications
   - User clicks "Send to Slack"
   - Articles are sent and marked as slack_notified = 1
   - Status updates to show 0 pending
   - Slack channel receives formatted message

✅ Scenario 3: New Articles
   - Scraper adds new high-profit articles
   - New articles have slack_notified = 0
   - Status shows new articles as pending
   - Old articles remain marked as sent

✅ Scenario 4: No Webhook Configured
   - API returns error: "Slack webhook URL not configured"
   - Frontend shows error alert
   - No database changes

✅ Scenario 5: Network Error
   - HTTP request times out or fails
   - API returns error with details
   - Articles remain unsent (slack_notified = 0)
   - User can retry

✅ Scenario 6: Test Mode
   - User clicks "Test Notification"
   - Sample message sent to Slack
   - No articles marked as sent
   - Success message indicates "(Test)"
