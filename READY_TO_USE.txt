ERROR HANDLING
================================================================================

If Network Error at Batch 10:

  ┌────────────────────────────────────────────────────┐
  │ ❌ Error                                           │
  │ Failed at batch 10: Network error.                 │
  │ Sent 90 articles before error.                     │
  └────────────────────────────────────────────────────┘

What to do:
  1. Fix network issue
  2. Click "Send All" again
  3. Starts from article 91 ✅
  4. No duplicates!

Why it works:
  • Articles 1-90 marked as sent (slack_notified = 1)
  • Next attempt skips them automatically
  • Backend filter: slack_notified = 0
  • Safe to retry anytime

================================================================================
DUPLICATE PREVENTION (BUILT-IN)
================================================================================

Database Column: slack_notified
  • 0 = Not sent yet
  • 1 = Already sent

How It Works:
  
  Query: SELECT * FROM articles 
         WHERE profit_score >= 5.0 
         AND slack_notified = 0
         LIMIT 10;
  
  Result: Only gets unsent articles ✅

After Send:
  
  UPDATE articles 
  SET slack_notified = 1 
  WHERE id IN (1, 2, 3, ..., 10);
  
  Result: These articles won't appear in next query ✅

Retry Safety:
  • Click "Send All" twice → No duplicates
  • Backend automatically skips sent articles
  • Slack channel stays clean

TROUBLESHOOTING

  → Solution: Scrape news first if none available

Problem: Progress bar stuck
  → Check: Network connection
  → Solution: Refresh page, try again

  → Read: Error shows which batch failed
  → Solution: Click "Send All" again (safe to retry)

Problem: Still showing pending after send
  → Wait: Status auto-refreshes after 1 second
  → Or: Manually refresh page

  → This shouldn't happen! (Built-in prevention)
